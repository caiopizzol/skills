# Write clearly

Make developer-facing text easy to understand and use.

## Write

1. Identify the reader and what they need to understand or do.
2. Verify technical facts from the source. Do not guess or add unsupported claims.
3. Keep a sentence only if it helps the reader understand, act, or avoid a mistake.
4. Use simple words, short sentences, and direct language. Match the project's terms and voice.
5. Remove repetition, filler, unnecessary background, and jargon that does not help the reader.
6. Use the smallest structure that stays clear. Add headings, lists, or examples only when they make the
   text easier to follow.
7. Read the result as someone new to the topic. Fix missing context, unclear steps, and vague references.

## Rules

- Preserve the author's intent and any requirements, warnings, constraints, or useful edge cases.
- Shorter is not always better. Easier to understand is the goal.
- Do not change technical meaning, API contracts, or code behavior. Report broader DX problems separately.
- If the source is unclear or contradictory, state the gap or ask instead of choosing a meaning.
