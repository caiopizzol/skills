# Build testable

Build the smallest real version that can answer one question with evidence.

## Build

1. Define the question this version needs to answer.
2. Decide what evidence would answer it.
3. Build the smallest end-to-end version that can produce that evidence.
4. Run it and verify the result.
5. Change one meaningful thing at a time and verify again.

## Rules

- Keep the core behavior real and observable.
- Do not add polish, options, abstractions, or imagined future needs.
- Do not remove what is needed to test the main risk.
- Prefer a thin working path over several incomplete parts.
- Record what was proven, what was not, and what to test next.
